01

Why use Storage Kernel

Por que usar o Storage Kernel

One contract in front of four providers, and what that buys you.

Um contrato na frente de quatro armazenamentos (no código, o provider_nameproviderName), e o que você ganha com isso.

  • Ask for a path, get the file. One call reads or writes text, bytes or a stream. There is no SDK to learn for each service.
  • Every provider behaves the same. Path resolution, defaults and errors do not change with the provider: a missing file is StoragePathNotFoundError, code strg_path_not_found, on a local disk, on S3, on GCP Storage and over SFTP. All four pass the same contract test suite.
  • Change providers, not code. Moving from S3 to GCP Storage changes the provider, its options and the installed package. Every read_contentreadContent call stays as written.
  • Tests without the cloud. The local-filesystem provider follows the same contract, so tests and CI make the same calls against a directory, with no network and no credentials.
  • What a service cannot do, the call says. A signed URL on a local disk raises StorageCapabilityNotSupportedError instead of returning a link that would not work.
  • Python and TypeScript, one contract. Each follows its own convention — read_content, readContent — and both share the behavior, the defaults and the error codes.
  • Peça um caminho, receba o arquivo. Uma chamada lê ou escreve texto, bytes ou um stream. Não há SDK para aprender a cada serviço.
  • Todo armazenamento se comporta igual. A resolução de caminhos, os defaults e os erros não mudam com o armazenamento: um arquivo ausente é StoragePathNotFoundError, código strg_path_not_found, num disco local, no S3, no GCP Storage e via SFTP. Os quatro passam pela mesma suíte de testes de contrato.
  • Troque o armazenamento, não o código. Sair do S3 para o GCP Storage muda o armazenamento, suas opções e o pacote instalado. Toda chamada a read_contentreadContent continua como foi escrita.
  • Testes sem nuvem. O armazenamento local-filesystem segue o mesmo contrato, então testes e CI fazem as mesmas chamadas contra um diretório, sem rede e sem credencial.
  • O que um serviço não faz, a chamada diz. Uma URL assinada num disco local levanta StorageCapabilityNotSupportedError em vez de devolver um link que não funcionaria.
  • Python e TypeScript, um contrato. Cada um segue a convenção da sua linguagem — read_content, readContent — e os dois compartilham comportamento, defaults e códigos de erro.

Install and first read

Instalação e primeira leitura

Nothing is bundled. Install the factory and the one provider you need.

Nada vem embutido. Instale a factory e o pacote do único armazenamento de que você precisa.

Step 1 · install the factory

Passo 1 · instale a factory

Your code imports everything from the factory: the location, the option classes, the errors and the types of the contract come through it. The contract and the shared core install with it, as dependencies. No provider yet — that is step 2, and it is a separate distribution so a service that only touches S3 never pulls a Google SDK or an SSH library.

O seu código importa tudo da factory: a location, as classes de opções, os erros e os tipos do contrato vêm por ela. O contrato e o core compartilhado são instalados junto, como dependências. Nenhum armazenamento ainda — isso é o passo 2, e ele é uma distribuição separada, então um serviço que só toca S3 nunca baixa um SDK do Google nem uma biblioteca de SSH.

contracts depends on nothing. A consumer that only declares types or catches storage errors installs that one package alone.

contracts não depende de nada. Quem só declara tipos ou captura erros de storage instala apenas esse pacote.

Step 2 · add a provider and read

Passo 2 · adicione um armazenamento e leia

Pick where the file lives. The call is identical on all four — only the provider name, the location field it roots on and its typed options change, which is the whole point of the contract.

Escolha onde o arquivo mora. A chamada é idêntica nos quatro — mudam apenas o nome do armazenamento, o campo da location em que ele se enraíza e suas opções tipadas, que é justamente o propósito do contrato.

Para desenvolvimento local, CI e testes. location.directory é a raiz e é obrigatório; todo caminho resolve abaixo dela, e um que tente escapar é rejeitado com StorageInvalidPathError.

Os diretórios pai são criados para você, porque create_directory_if_not_existscreateDirectoryIfNotExists vem como verdadeiro. Os aliases local e filesystem também selecionam este armazenamento.

03

How a path resolves

Como um caminho é resolvido

A location roots the client. The path each call asks for is resolved under it, and the provider maps the result to whatever its service calls a place.

Uma location enraíza o client. O caminho que cada chamada pede é resolvido abaixo dela, e o armazenamento mapeia o resultado para o que o serviço dele chama de lugar.

location.bucket · location.prefix · path
app-files    /reports    /2026/summary.csv
app-files/reports/2026/summary.csv

On S3 that is an object key under a bucket; on the local filesystem a file under a directory; over SFTP a path under a remote directory. The call that produced it was the same in all three.

No S3 isso é uma chave de objeto sob um bucket; no filesystem local, um arquivo sob um diretório; via SFTP, um caminho sob um diretório remoto. A chamada que produziu isso foi a mesma nos três casos.

location.directory local-filesystem
sftp		 The filesystem root. Mandatory and non-empty for the local provider. For SFTP it selects the remote root, falling back to root_directoryrootDirectory and then to .. A raiz no filesystem. Obrigatória e não-vazia no armazenamento local. No SFTP ela seleciona a raiz remota, caindo para root_directoryrootDirectory e depois para ..

path all fouros quatro What the call asks for, as a plain string. Always / separated, whatever the platform underneath. O que a chamada pede, como string simples. Sempre separado por /, seja qual for a plataforma embaixo.

A field a provider does not read is ignored, not rejected. A directory handed to S3 never becomes part of the object key, and nothing reports it — the write lands at the bucket root instead of under the namespace you meant.

Um campo que o armazenamento não lê é ignorado, não rejeitado. Um directory entregue ao S3 nunca entra na chave do objeto, e nada avisa — a escrita cai na raiz do bucket em vez de dentro do namespace que você quis.

Normalization

Normalização

The same everywhere: backslashes become /, duplicate separators collapse, a leading ./ and any leading or trailing slash are dropped, and a .. segment is rejected with StorageInvalidPathError.

Igual em todo lugar: contrabarras viram /, separadores duplicados colapsam, um ./ inicial e qualquer barra no começo ou no fim caem fora, e um segmento .. é rejeitado com StorageInvalidPathError.

The local provider adds one more check after resolving: the absolute result has to stay below the configured directory, so a symlink or an oddly encoded path cannot walk out of it.

O armazenamento local acrescenta mais uma checagem depois de resolver: o resultado absoluto precisa continuar abaixo do diretório configurado, então um symlink ou um caminho com encoding estranho não consegue sair dele.

An operation-level location replaces the client's entirely. It is not merged field by field, so naming another bucket for one call cannot leave the old prefix quietly attached.

Uma location no nível da operação substitui a do client por inteiro. Ela não é mesclada campo a campo, então nomear outro bucket numa chamada não deixa o prefix antigo grudado em silêncio.

04

Text, bytes and streams

Texto, bytes e streams

Seventeen methods in the contract, and the four you reach for first move whole values.

Dezessete métodos no contrato, e os quatro que você usa primeiro movem valores inteiros.

Whole values

Valores inteiros

Text goes through send_contentsendContent and read_contentreadContent, UTF-8 unless encoding says otherwise. Bytes go through send_binarysendBinary and read_binaryreadBinary.

Texto passa por send_contentsendContent e read_contentreadContent, em UTF-8 a menos que encoding diga outra coisa. Bytes passam por send_binarysendBinary e read_binaryreadBinary.

A full read buffers the entire payload, which is exactly why the stream methods exist beside them. A missing file is StoragePathNotFoundError, on every provider.

Uma leitura completa carrega o payload inteiro na memória, que é justamente por que os métodos de stream existem ao lado. Um arquivo ausente é StoragePathNotFoundError, em todo armazenamento.

A write can carry content_typecontentType and object metadata, and can turn overwrite off for that call alone.

Uma escrita pode carregar content_typecontentType e metadata do objeto, e pode desligar o overwrite só naquela chamada.

whole valuesvalores inteiros 
from storage_kernel.factory import SendContentOptions

await storage.send_content(
    "docs/readme.md",
    "# Hello",
    SendContentOptions(
        content_type="text/markdown",
        overwrite=False,
    ),
)

text = await storage.read_content("docs/readme.md")
data = await storage.read_binary("images/avatar.png")
await storage.sendContent(
    'docs/readme.md',
    '# Hello',
    { contentType: 'text/markdown', overwrite: false },

const text = await storage.readContent('docs/readme.md');
const data = await storage.readBinary('images/avatar.png');

Streams

Streams

read_streamreadStream hands back an async byte iterable that carries close(). Reading to the end releases it; a reader that stops early has to call close(), which is idempotent, so calling it anyway is always correct.

read_streamreadStream devolve um iterável assíncrono de bytes que carrega close(). Ler até o fim o libera; quem para antes precisa chamar close(), que é idempotente, então chamá-lo de qualquer jeito está sempre certo.

create_upload_streamcreateUploadStream hands back a writable handle with five methods: write, write_textwriteText, write_text_linewriteTextLine, then close() to finish or abort() to discard. close() waits for the provider to actually finish, and after either one another write fails with a normalized error rather than quietly doing nothing.

create_upload_streamcreateUploadStream devolve um handle de escrita com cinco métodos: write, write_textwriteText, write_text_linewriteTextLine, e então close() para concluir ou abort() para descartar. close() espera o armazenamento realmente concluir, e depois de qualquer um dos dois outra escrita falha com um erro normalizado em vez de não fazer nada em silêncio.

send_streamsendStream takes text, bytes or a stream and writes it in parts through that same handle, never buffering the whole payload.

send_streamsendStream recebe texto, bytes ou um stream e escreve em partes por esse mesmo handle, sem nunca acumular o payload inteiro.

URLs and copies

URLs e cópias

create_signed_urlcreateSignedUrl takes an action — read, write or delete — and expires_in_secondsexpiresInSeconds. A signed write forwards content_typecontentType and string metadata to the signature.

Both clouds sign with Signature Version 4, so a URL lives seven days at most. A boto3 client you inject has to be built with Config(signature_version="s3v4").

As duas nuvens assinam com a Signature Version 4, então uma URL vive no máximo sete dias. Um client boto3 que você injeta precisa ser construído com Config(signature_version="s3v4").

get_public_urlgetPublicUrl percent-encodes each path segment and keeps /, so a # or ? in a name survives. get_public_urlgetPublicUrl aplica percent-encoding em cada segmento e preserva /, então um # ou ? num nome sobrevive. Credentials are explicit when you pass them and fall back to the cloud SDK's own chain when you do not — the AWS provider chain, or Application Default Credentials on GCP.

Injetar um client mantém aquele client de SDK sob o seu ciclo de vida. O close() libera apenas o que o kernel criou: o client S3 e a conexão SFTP que ele abriu, e o client do Google que ele construiu. SFTP host identity

Identidade do host SFTP

The SFTP provider will not open a connection without being told how to verify the server. Exactly one policy is required, and there is no default:

O armazenamento SFTP não abre conexão sem que se diga como verificar o servidor. Exatamente uma política é obrigatória, e não existe default:

  • known_hosts_pathknownHostsPath — an OpenSSH known_hosts file.
  • host_key_sha256hostKeySha256 — a fingerprint in SHA256:<base64> form.
  • host_verifierhostVerifier — your own predicate over the host key.
  • dangerously_disable_host_key_verificationdangerouslyDisableHostKeyVerification — the bypass. It accepts any host key, which means accepting a machine-in-the-middle, so it belongs to a disposable local fixture and nowhere else. It is named the way it is so it cannot be switched on without reading what it does.
  • known_hosts_pathknownHostsPath — um arquivo known_hosts do OpenSSH.
  • host_key_sha256hostKeySha256 — uma fingerprint no formato SHA256:<base64>.
  • host_verifierhostVerifier — seu próprio predicado sobre a chave do host.
  • dangerously_disable_host_key_verificationdangerouslyDisableHostKeyVerification — o bypass. Ele aceita qualquer chave de host, o que significa aceitar um ataque de intermediário, então serve para uma fixture local descartável e nada mais. O nome é esse justamente para não ser ligado sem se ler o que ele faz.

Two policies at once, or a malformed fingerprint, is a StorageKernelConfigurationError rather than a quiet fallback to something weaker.

Duas políticas ao mesmo tempo, ou uma fingerprint malformada, é um StorageKernelConfigurationError em vez de uma queda silenciosa para algo mais fraco.

Each connection phase is bounded, and the two implementations bound them differently — the SDKs underneath are not the same. Python names four: connect_timeout at 10s, banner_timeout at 15s, auth_timeout at 30s and channel_timeout at 60s. The first one matters most: paramiko leaves the connect socket blocking when no timeout is given, so without it a TCP handshake is bounded only by the operating system. TypeScript takes readyTimeout, in milliseconds, over the whole handshake.

Cada fase da conexão tem um limite, e as duas implementações limitam de formas diferentes — os SDKs por baixo não são os mesmos. O Python nomeia quatro: connect_timeout em 10s, banner_timeout em 15s, auth_timeout em 30s e channel_timeout em 60s. O primeiro é o que mais importa: o paramiko deixa o socket de conexão bloqueante quando nenhum timeout é dado, então sem ele o handshake TCP fica limitado apenas pelo sistema operacional. O TypeScript recebe readyTimeout, em milissegundos, sobre o handshake inteiro.

A failure names both sides: path is always the path you passed, and the message adds the remote one — Storage path not found in sftp: missing.txt (provider path: /upload/missing.txt).

Uma falha nomeia os dois lados: path é sempre o caminho que você passou, e a mensagem acrescenta o remoto — Storage path not found in sftp: missing.txt (provider path: /upload/missing.txt).

The Python provider also disables SSH agent and default-key discovery, so a key is used because you named it, not because it happened to be in the environment.

O armazenamento Python também desliga o SSH agent e a descoberta de chaves default, então uma chave é usada porque você a nomeou, não porque ela por acaso estava no ambiente.

Errors are part of the contract

Erros fazem parte do contrato

Every error carries name and code, plus provider, path, provider_codeproviderCode and cause when the failure exposes them.

Todo erro carrega name e code, mais provider, path, provider_codeproviderCode e cause quando a falha os expõe.

Three fields identify a failure. name is the class. code is the kernel's own, always present and frozen, the same string in both languages — compare it at a process boundary, where a class cannot travel. provider_codeproviderCode is the vendor's — NoSuchKey on S3, 404 on GCP Storage, SFTP status 2, ENOENT on a local disk, ECONNREFUSED when the service never answered — and is absent when the SDK gave none.

Três campos identificam uma falha. name é a classe. code é do próprio kernel, sempre presente e congelado, a mesma string nas duas linguagens — compare-o numa fronteira entre processos, onde uma classe não viaja. provider_codeproviderCode é o do fornecedor — NoSuchKey no S3, 404 no GCP Storage, status SFTP 2, ENOENT num disco local, ECONNREFUSED quando o serviço nem respondeu — e fica ausente quando o SDK não deu nenhum.

Only not found and permission denied are normalized, because only those two are what a caller branches on without knowing which service is behind the contract. Their message names the provider and the path: Storage path not found in aws-s3: 2026/summary.csv.

Só não encontrado e permissão negada são normalizados, porque só esses dois são aquilo em que quem chama ramifica sem saber qual serviço está atrás do contrato. A mensagem deles nomeia o armazenamento e o caminho: Storage path not found in aws-s3: 2026/summary.csv.

Everything else becomes StorageProviderError and keeps the message the provider produced. Wrapping adds context, it never translates: provider, path and provider_codeproviderCode are attached and the original stays in cause.

Todo o resto vira StorageProviderError e preserva a mensagem que o armazenamento produziu. O wrap acrescenta contexto, nunca traduz: provider, path e provider_codeproviderCode são anexados e o original fica em cause.

An error that already is a StorageKernelError is never re-wrapped and never reclassified. It receives only the context fields it was missing, so a failure raised deep inside a client still reports where it came from.

Um erro que já é StorageKernelError nunca é reembrulhado nem reclassificado. Ele recebe apenas os campos de contexto que faltavam, então uma falha levantada lá no fundo de um client continua dizendo de onde veio.

Observability, and your own provider

Observabilidade, e seu próprio armazenamento

Silent unless you hand it a logger, and open to a provider the kernel has never heard of.

Silencioso a menos que você entregue um logger, e aberto a um armazenamento que o kernel nunca viu.

One line per operation

Uma linha por operação

Pass a logger and the client writes one line per operation. Without one it says nothing: the logger is the only sink, and there is no console fallback. The levels are fixed by the contract, not by each provider: starts and completions on debug, a missing path or an aborted upload on warningwarn, permission and provider failures on error.

Passe um logger e o client escreve uma linha por operação. Sem ele, não diz nada: o logger é o único destino, e não há console de reserva. Os níveis são fixados pelo contrato, não por cada armazenamento: início e conclusão em debug, caminho ausente ou upload abortado em warningwarn, falhas de permissão e do armazenamento em error.

Each line is one sentence naming the operation, the path, the provider and its bucket, directory or prefix — Reading 2026/summary.csv from aws-s3 bucket app-files under reports. Content, credentials and object metadata never appear in it.

Cada linha é uma frase que nomeia a operação, o caminho, o armazenamento e seu bucket, diretório ou prefix — Reading 2026/summary.csv from aws-s3 bucket app-files under reports. Conteúdo, credenciais e metadados de objeto nunca aparecem nela.

Completion is reported when it actually happened: a read stream after it has been fully consumed, an upload after close() succeeded — not when the call returned. A logger may implement any subset of the four levels; a line at a level it lacks is dropped.

A conclusão é reportada quando realmente aconteceu: um stream de leitura depois de consumido por inteiro, um upload depois de close() ter dado certo — não quando a chamada retornou. Um logger pode implementar qualquer subconjunto dos quatro níveis; uma linha num nível que ele não tem é descartada.

One contract, and what it will not fake

Um contrato, e o que ele não vai fingir

Every provider implements the same seventeen asynchronous methods. Where a service genuinely cannot do something, the call says so instead of improvising.

Todo armazenamento implementa os mesmos dezessete métodos assíncronos. Onde um serviço realmente não consegue fazer algo, a chamada diz isso em vez de improvisar.

  • Nothing is emulated. create_signed_urlcreateSignedUrl on the local filesystem raises StorageCapabilityNotSupportedError rather than inventing a URL that would not work.
  • Streams are real streams. Reads and progressive uploads use the provider's own stream where it has one, so a multi-gigabyte file never has to fit in memory.
  • Provider options never leak. region belongs to AWS, project_idprojectId to GCP, host and key material to SFTP. The shared contract knows none of them.
  • Injected clients stay yours. Hand a provider an SDK client you built and close() leaves it alone — the kernel releases only what it created.
  • An empty path means the configured root, and only on S3, GCP Storage and SFTP. The local filesystem provider rejects it for every operation.
  • A per-call location replaces the client's, whole. Locations are never merged field by field, so a call that names another bucket cannot silently keep the old prefix.
  • Nada é emulado. create_signed_urlcreateSignedUrl no filesystem local levanta StorageCapabilityNotSupportedError em vez de inventar uma URL que não funcionaria.
  • Streams são streams de verdade. Leituras e uploads progressivos usam o stream do próprio armazenamento quando ele tem um, então um arquivo de vários gigabytes nunca precisa caber na memória.
  • Opções de armazenamento não vazam. region é da AWS, project_idprojectId é do GCP, host e material de chave são do SFTP. O contrato compartilhado não conhece nenhum deles.
  • Clients injetados continuam seus. Entregue a um armazenamento um client de SDK que você construiu e o close() não encosta nele — o kernel libera apenas o que ele mesmo criou.
  • Um caminho vazio significa a raiz configurada, e só no S3, no GCP Storage e no SFTP. O armazenamento de filesystem local o rejeita em toda operação.
  • Uma location por chamada substitui a do client, inteira. Locations nunca são mescladas campo a campo, então uma chamada que nomeia outro bucket não consegue manter o prefix antigo em silêncio.

Overwrite is on by default and can be turned off per call. The check always runs against the destination, and a blocked write is StoragePathAlreadyExistsError. On the local filesystem and over SFTP the file is opened exclusively, so one that appears between the check and the write is refused rather than replaced.

Sobrescrever é o padrão e pode ser desligado por chamada. A verificação sempre roda contra o destino, e uma escrita bloqueada é StoragePathAlreadyExistsError. No filesystem local e no SFTP o arquivo é aberto de forma exclusiva, então um que apareça entre a verificação e a escrita é recusado em vez de substituído.

Changed · breaking

Alterado · breaking

  • A path is a plain string. Every operation took StoragePath("a/b.txt") and now takes "a/b.txt". StoragePath is gone from the contract.
  • A writable stream finishes with close(), where it said end(). abort() still discards.
  • code changed owner. It held the vendor's identifier, which moved to provider_code. code is now the kernel's own, always present and frozen: strg_path_not_found, strg_path_already_exists, strg_permission_denied, strg_invalid_path, strg_capability_not_supported, strg_invalid_configuration, strg_unexpected. StorageErrorCode is a StrEnum of those seven.
  • provider_code is what the vendor's protocol called the failure: the errno name on a local disk, ENOENT, where it was a number; the SFTP status the server sent; the operating-system error, such as ECONNREFUSED, when the service never answered; a plain int on GCP Storage. TypeScript reports the same values.
  • StorageConfigurationError is now StorageKernelConfigurationError, with no alias. Its code is strg_invalid_configuration.
  • A not-found or permission failure names the provider and the path in its message, in the same words as TypeScript. Any other failure keeps the message the SDK produced, where it was replaced by one of the provider's own.
  • A log line is one string, and the logger is the only sink. The context argument and the debug option are gone, and each line says what happened and where. logging.getLogger("my-app") is a drop-in.
  • read_stream returns a stream that carries an idempotent close(), so a reader that stops early can release the socket, descriptor or channel it holds. A custom provider subclasses IterableStorageReadableStream.
  • send_stream takes text, bytes or a stream, with SendStreamOptions.
  • The S3 provider names its SDK configuration client_options, as TypeScript does. It was client_config.
  • The create_*_storage_client functions lose their third parameter: inject the SDK client through client in the provider options.
  • Errors are built from one StorageKernelErrorOptions, and write_text and write_text_line take a WriteTextOptions instead of an encoding keyword — the same call shape as TypeScript.
  • Helpers take the names TypeScript uses — join_storage_path, resolve_storage_location — and drop the storage prefix where the type they return already says it: normalize_provider_error, assert_client_contract and nine more. STORAGE_PROVIDER_TARGETS is STORAGE_PROVIDER_TARGET_BY_NAME. Breaking for a custom provider importing them.
  • Signed URLs use Signature Version 4 on both clouds, so they live seven days at most. A boto3 client you inject has to be built with signature_version="s3v4".
  • overwrite=False on SFTP is enforced by the server: the file is opened with an exclusive create, so one created between the check and the write is refused instead of replaced.
  • An SFTP failure carries your path in path, and names the remote one in its message.
  • Um caminho é uma string simples. Toda operação recebia StoragePath("a/b.txt") e agora recebe "a/b.txt". StoragePath saiu do contrato.
  • Um stream de escrita termina com close(), onde dizia end(). abort() continua descartando.
  • code mudou de dono. Ele guardava o identificador do fornecedor, que foi para provider_code. code agora é do próprio kernel, sempre presente e congelado: strg_path_not_found, strg_path_already_exists, strg_permission_denied, strg_invalid_path, strg_capability_not_supported, strg_invalid_configuration, strg_unexpected. StorageErrorCode é um StrEnum desses sete.

O TypeScript reporta os mesmos valores.
  • StorageConfigurationError agora é StorageKernelConfigurationError, sem alias. O code é strg_invalid_configuration.
  • Uma falha de não encontrado ou de permissão nomeia o armazenamento e o caminho na mensagem, com as mesmas palavras do TypeScript. Qualquer outra falha preserva a mensagem que o SDK produziu, onde antes era trocada por uma do próprio armazenamento.
  • Uma linha de log é uma string, e o logger é o único destino. O argumento de contexto e a opção debug saíram, e cada linha diz o que aconteceu e onde. logging.getLogger("my-app") serve direto.
